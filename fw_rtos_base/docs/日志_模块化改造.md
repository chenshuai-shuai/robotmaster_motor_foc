### 两个设计取舍（已写进代码注释，供以后照抄）

1. **服务模块用"显式停用桩"，纯硬件驱动仍用"严格空对象"（K3 精化）**
   `J8108_Task` 的 API 被**通用协议层**（CmdRx）和 UI 层调用。若按 K3 编成空对象，那些调用点必须逐个 `#if` 包住 —— 等于让协议层复制一份"电机命令表"（维护负担大且容易漏）。
   折中：桩**不碰任何硬件**，但每个 API 都**诚实回答"我没在跑"**（`J8108_ReqResult()` → `J8108_RES_DISABLED` → 协议层回 `@ERR 4`）。
   硬件类驱动（`disp/sd/can`，不该被通用层调用）继续用 K3 空对象。
2. **用依赖规则替代代码守卫**
   原计划要给 `Monitor → Oled_UiDraw()` 加 `#if FEATURE_DISP_UI`。实际**不需要**：依赖矩阵已禁止 `MONITOR=1 && DISP_UI=0` 这种组合存在 → 少一处散布的 `#if`。

### 三个实测发现（都已固化成断言/注释）

1. **fail-fast 真的抓到了漏网依赖**：第一次构建 10 个链接错误 —— `it.c` 的中断处理器、HAL 的 `g_sd_step`、FatFs 的 `get_fattime`/`disk_*` 都还指着被清空的 SD 文件。这正是 K3/R3 想要的效果：**忘 guard = 链接期报错，而不是运行时静默**。修法是把这些"平台胶水"一并纳入同一宏，而不是回退。
2. **"空对象"不是唯一正解**：`sd_sdio.c` 被清空后，HAL 文件里一处诊断写路径标记（`g_sd_step`）没了定义。为一个 HAL 文件加项目宏不值当 → 给 SD 关闭态留**一个中性定义**（0 = 从未走步），与 M2 的"显式停用桩"同一先例。
3. **`#warning` 不能放共享头**：DISP_DEV/MINIMAL 从 6 条告警涨到 **18 条同文告警**（每个 include `feature_config.h` 的编译单元各报一次）→ 移到组装根 `main.c`，降到 **1 条**。噪声也是缺陷：它会淹没真告警。

## M4 · 自检 `#ST` + 各模块 SelfTest（2026-09-19 18:4x）

新增命令 `#ST` / `#ST <模块>`：分块调试的入口（"我烧的这版里，每个模块到底活没活"）。

### 自检码语义（实现 + 手册 + 断言三处一致）

| 码 | 含义 | 判据（全部非破坏性只读，不发帧/不写外设） |
|---|---|---|
| `0` | 本固件未编译该模块 | 见开机 `@BOOT` 横幅 |
| `1` | OK | — |
| `2` | WARN（活着但状态可疑） | `can` 总线错误 · `disp` 2s 没刷新 · `key` 一直按住（卡住/短路）· `monitor` 循环 500ms 没动静 |
| `3` | FAIL | 任务没起来 / 设备没注册 / 引脚模式被改 / 控制器启动失败 |

### 各模块判据

| 模块 | 实现 | 只读什么 |
|---|---|---|
| `disp` | `Oled_SelfTest()` | 最近一次绘制时刻（新增一个 `volatile` 心跳，无阻塞） |
| `led` | `Led_SelfTest()` | 回读 `GPIOx->MODER`：LED 引脚还是不是推挽输出 |
| `key` | `Key_SelfTest()` | 事件组是否存在 + 按住时长是否超 `KEYC_STUCK_MS` |
| `can` | `J8108_CanSelfTest()` | `J8108_ST_*`（READY/INIT_OK→1 · BUS_ERR→2 · INIT_FAIL→3） |
| `j8108` | `J8108_SelfTest()` | 控制任务句柄 + 设备是否注册 |
| `monitor` | `Monitor_SelfTest()` | 循环心跳时间戳 |

### 三条设计取舍

1. **未编译的模块也占位（返回 0）**：汇总行永远 6 个键。理由是"少一个键"比"错一个键"更糟 —— 上位机脚本可以无脑按固定键解析。
2. **有 FAIL 就整条回包变 `@ERR 6`**：自检结果不能被当成全绿（`@OK` 只表示"这条命令被接受了"，不能表示"一切正常"）。
3. **单模块查询未编译 → `@ERR 9 ST module=x code=255`**：与汇总行的 `0` 互为补充 —— 你专门问的模块不在，就要明确告诉你。

顺带：`#HELP` 从 1 行拆成 3 行（原来那行 112 字符，逼近 127B 截断老坑）。

### 意外收获：契约头自足性被编译期抓到

`Led_Task.h` 用了 `uint8_t` 却没包含 `<stdint.h>` —— 加原型后立刻编译报错（"unknown type name 'uint8_t'"）。
这正是规范 **R4（契约头任何组合可单独 include）** 的价值：**头文件必须自足**。已修（补 `<stdint.h>`）。

### 台架实测（v0.1.64-dev）抓到的缺陷：汇总回包漏了命令名

实测回包是 `@OK disp=1 led=1 key=1 can=1 j8108=1 monitor=1` —— **少了 `ST` 命令名**（其它命令都是 `@OK <CMD> …`，手册写的也是 `@OK ST disp=1 …`）。

- **修**：`reply_ok("ST %s", line)`
- **防**：新增断言"所有 `reply_ok` 的首字段必须是命令名（或变量形式 `%s`）"—— 机械防住这一类"回包与协议口径不一致"，不靠人眼。
- **教训（值得记）**：M4 我写的断言只查了*载荷*文本（`code=255`、`self-test FAIL`），没查*回包格式* → 台架把它补上了。**断言要覆盖格式，不能只覆盖内容。**

台架其余项目全对：`#ST disp` → `@OK ST disp=1` ✓ · `#ST foo` → `@ERR 2 ST usage: …` ✓ · 6 个模块全 `1` ✓ · `#HELP` 3 行内容完整（首行在串口助手里被拆成两段显示，是接收分块+时间戳，不是固件截断）✓ · 栈余量/堆与 M3 一致 ✓。
