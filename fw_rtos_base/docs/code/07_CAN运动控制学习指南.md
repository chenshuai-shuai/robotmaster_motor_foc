## 1. 先建立直觉：电机为什么会"听话"

### 1.1 三层环，越靠内越快

```
        位置环(慢,10~100Hz)     速度环(中,100Hz~1kHz)     电流环(快,5~20kHz)     电机本体
 目标角 ─────►[P]─────► 目标速度 ─────►[PI]─────► 目标电流 ─────►[PI]─────► 电压/PWM ─► 绕组
   ▲                    ▲                        ▲                          │
   └── 编码器 ──────────┴────────────────────────┴──────────── 电流采样 ─────┘
```

**为什么越靠内越快**：内环要"抵消外环还没来得及知道的扰动"（电流环压电源波动、速度环压摩擦/负载）。内环慢于外环 → 系统必震荡。

**8108 厂商固件在电机内部已经把三环都做好了**（包括电流环、FOC、编码器解算、温度/错误保护）。所以对 A 板来说，电机就是一个"**输入力矩（或位置/速度），输出轴就动**"的黑盒子。

### 1.2 MIT 帧 = "力矩接口"思想

MIT Cheetah 风格的一帧 8 字节里塞 5 个量：

```
位置 p (16bit) | 速度 v (12bit) | Kp (12bit) | Kd (12bit) | 力矩 t (12bit)
```

电机内部按 **T_out = Kp·(p_cmd − p) + Kd·(v_cmd − v) + t_ff** 执行。于是：

| 你想让电机做 | 发什么 | 谁来闭环 |
|---|---|---|
| 纯力矩（力矩模式） | Kp=0, Kd=0, t=τ | 谁都不闭环（你要自己闭环） |
| 阻尼/刹车 | Kp=0, Kd=k>0, t=0 | 电机内部速度环（软） |
| 速度控制 | Kp=0, Kd=小, t=你的速度环输出 | **你在 A 板上闭环**（本工程的做法） |
| 位置控制 | p=目标, Kp=k, Kd=kd | 电机内部（位置环） |
| 柔顺/阻抗 | p=p₀, Kp=K, Kd=D | 电机内部（阻抗控制） |

**关键领悟**：MIT 帧的"力矩 t"是**叠加量**。当 `v_cmd=0` 且 `Kd>0` 时，电机内部会算 `Kd·(0−v)` = **一个与速度成正比的阻力**——这就是"内环阻尼"。它既能帮我们稳定（阻尼），也会偷偷吃掉力矩（阻力）。**这两面性是本工程速度模式调参的核心矛盾之一**（详见 §4.2）。

### 1.3 为什么用 CAN 而不是 PWM/串口

| 特性 | CAN | 串口(RS232/TTL) | PWM |
|---|---|---|---|
| 抗干扰 | ★★★（差分、CRC、自动重传） | ★ | ★★（模拟量易受扰） |
| 多节点 | ★★★（总线式，ID 寻址） | ★（点对点） | ★ |
| 速率 | 1 Mbps（本工程） | 115200~1M | — |
| 传"力矩数值" | ✅ 精确、可监控 | ✅（但慢） | ❌（只能传占空比） |
| 实时性 | 8 字节 @1Mbps ≈ 130 µs | 8 字节 @115200 ≈ 700 µs | 立即 |

1 Mbps 下，一帧 8 字节 ≈ **130 µs**（含仲裁/CRC/ACK 位）。200 Hz 控制帧只占 **2.6%** 带宽，所以 1 kHz 控制帧也做得起（占 13%）——**带宽不是瓶颈，延时和采样才是**。

## 2. 8108 协议精讲（一条命令从字节到轴动）

### 2.1 三种帧

| 方向 | CAN ID | 用途 | 内容 |
|---|---|---|---|
| 下发 | **0x001**（命令帧） | 使能/失能/零点/重启/清错 | 8 字节，仅最后 1 字节不同：`FC`=使能 `FD`=失能 `FE`=零点 `FB`=重启 `FA`=清错 |
| 下发 | **0x201**（MIT 帧） | 运动控制 | p16+v12+kp12+kd12+t12 |
| 上传 | **0x781**（反馈帧） | 状态回报 | ERR8 + POS16 + VEL12 + T12 + TMos8 + TMotor8 |

### 2.2 手算练习 A：把一个力矩编成字节

规则：每个物理量先**归一化到 [−1,1]**（除以各自量程），再映射到无符号整数，再拼位。

以双编 8108 为例（**输出端量程**：P ±12.56 rad、V ±45 rad/s、T ±18 N·m、Kp ≤500、Kd ≤5）：

> 目标：`p=0, v=0, Kp=0, Kd=1.0, T=0.15 N·m`

```
Kd  : 1.0 / 5.0 = 0.2 → (0.2+1)/2 × 4095 = 2457 = 0x999 → 12bit
T   : 0.15 / 18 = 0.008333 → (0.008333+1)/2 × 4095 = 2064 = 0x810 → 12bit
p   : 0 → (0+1)/2 × 65535 = 32768 = 0x8000
v   : 0 → (0+1)/2 × 4095 = 2048 = 0x800
拼帧: p16<<48 | v12<<36 | kp12<<24 | kd12<<12 | t12 = 80 00 80 00 09 99 08 10
```

**自己验证**：`#SETP 0 0 0 1.0 0.15` 就是这个效果（原始直通，需先 `#SET safety 0`）。

### 2.3 手算练习 B：反馈解包

一帧示例：`00 8A CE 7F F7 FF 67 4B`

```
Byte0 = 0x00          → ERR 位全 0（无过载/过温/过流/过压/欠压）
POS16 = 0x8ACE        → (0x8ACE/65535×2−1)×12.56 rad = 0.0371 rad = 2.12°
VEL12 = 0x7FF (取位)→ (…) → −0.01 deg/s
T12   = 0xFF7         → −0.004 N·m
TMos  = 0x67=103 → 40.4℃ ; TMotor = 0x4B=75 → 29.4℃（视换算）
```
（**注意**：ERR 在**最高字节**，别按"低字节是错误位"想当然——这是常见踩坑点。）

### 2.4 使能与握手的真实时序

```
A板                          8108
 │── 0x201: .. .. .. .. .. .. .. FC ──►│   (使能)   电机回 0x781 反馈
 │◄──── 0x781 反馈（首次出现 = ACK）───│
 │ 20ms 内没收到 → 判定没使能成功 → abort 邮箱 + 报错
```
**为什么必须"发完等反馈"**：CAN 发送成功只代表"帧发到总线上且被应答"，不代表电机真的使能了。所以握手的判据是"**反馈帧里的状态变了**"。

## 3. 转得好不好，先分类：症状 → 机理 → 判据

| 症状 | 常见机理 | 怎么判据（用我们的工具） |
|---|---|---|
| **完全不动** | ① 没使能 ② CAN 无 ACK（线/终端电阻/ID 错） ③ 目标为 0 ④ 力矩被限幅卡在 0 | `#STAT` 看 `mode/en/err`；`@EVT LINKLOST what=noack`；`#GET GAINS` 看 TMAX/TRATE |
| **起动慢（几秒才动）** | 静摩擦 > 比例项，积分攒太慢 | 实测：静摩擦 0.25 N·m、`Kp_v×e=0.03`、`Ki=0.0003` → 要 80 s |
| **抖/嗡（高频）** | 增益过高（Kp 太大）或内环带宽不足；采样延时大 | 抖动频率 ≈ 1/(2~3×控制周期) → 试降 Kp 或升到 1kHz 控制 |
| **卡卡的（低频黏滑）** | 静摩擦≫动摩擦 + 无前馈 → 粘住/突滑循环 | `vel` 方波状起伏（5↔17 dps），`T` 峰值出现在 `vel` 低谷 |
| **没劲（转不动/带不动）** | ① 力矩上限太低（`#LIM T`） ② 内环阻尼吃掉大半 ③ 前馈缺失 | 看 `T` 是否贴着 `#LIM T` 上限；对比 `#V 10 1.0 0.15` 与 `#V 10 0.3 0.15` |
| **速度偏高/超调** | 积分饱和（超调后回不来） | `vel` 均值 > 目标 10% 以上（实测 11~15 vs 10） |
| **正反转不对称** | 重力分量（竖直装）或零点偏移 | 对比正反两向同目标的稳态 `T`（差 = 重力分量） |
| **转一会停** | 心跳超时退 DAMP | `@EVT TIMEOUT mode=DAMP` → 要么持续发命令，要么 `#WD 0` |
| **位置慢慢漂** | 速度环有静差（纯 P） | 加 `KI_V` 或用位置模式 |

> 判据都在**遥测流**里：`#TEL 100` 打开 10 Hz 遥测，看 `vel/T/pos/age` 四条曲线。

## 4. "转得好"的十个手段（按性价比排序）

### 4.1 ★★★★★ 摩擦前馈（本工程已实现 `TFF`）

**物理**：库仑摩擦 ≈ 恒定力矩，方向与运动方向相反。它占小负载关节力矩的 **60~90%**（实测：维持转动只需 0.1 N·m，而 PI 的比例项只有 0.03 N·m）。

**做法**：`T += sign(目标速度) × TFF`，`TFF` 取"维持匀速转动所需的力矩"。

```c
/* ctrl_core.c 速度模式里（简化） */
float t_ff = (s->set_applied >= 0.0f) ? p->tff_nm : -p->tff_nm;  /* 按方向取号！ */
t = kp_v * err + s->integ + t_ff + s->tff;
```
**为什么必须按方向取号**：若固定 `+TFF`，反向运动时它会变成"拖拽"，误差翻倍 → 反向明显更差。

### 4.2 ★★★★★ 认识并主动管理"内环阻尼"

MIT 帧的 `Kd` 在 `v_cmd=0` 时就是阻力 `−Kd×v`。数值感：`Kd=1.0`、10 °/s（=0.175 rad/s）→ **0.175 N·m**，与摩擦同量级。

- 好处：天然阻尼，抗震荡；
- 坏处：**吃掉你一半力矩**，而且它随速度变化 → 高增益环更易震荡。

**动作**：速度模式把 `KD_DAMP` 降到 0.2~0.5（保留一点阻尼做稳定），把"阻尼预算"从内环挪到外环（外环的 Kp/Ki 可以更精确地按误差分配）。

### 4.3 ★★★★☆ 力矩斜率限制 TRATE（本工程已实现）

一周期内力矩最大变化 = `TRATE × dt`。`TRATE=20 N·m/s`、`dt=5ms` → 每拍最多 0.1 N·m。

- 作用：把"阶跃"变成"斜坡"，避免小惯量关节被一个周期的大力矩**瞬间加速过冲**（极限环的根源）；
- 代价：响应变慢。**先设小，抖就减、慢就加**。
- 已实现：`ctrl_t_slew()`；触发时上报 `@EVT LIMIT what=trate`（**消退去抖 1s**，不会刷屏）。

### 4.4 ★★★★☆ 增益标定的"结构化起调法"

不要盲试。按下面顺序，每步只改一个量：

```
Step0  TFF=0, KD_DAMP=0.2, TRATE=5, KI_V=0, KP_V=0    → 静止（系统无输出）
Step1  缓慢加 KP_V，直到"刚好能平滑转动"（典型 0.002~0.01）
       判据：vel 能跟上目标且无明显反向过冲
Step2  加 TFF ≈ 实测维持力矩（0.1~0.2）→ 起步立刻变快、误差变小
       判据：起步时间 <0.5s；vel 均值≈目标
Step3  加 KI_V 消静差（每次 ×2，上限 ~0.05）
       判据：vel 均值与目标差 <5%，且不出现低频来回摆
Step4  调 TRATE 到"不抖的最大值"（10~50）
Step5  最后调 KD_DAMP（0.2~0.5），换更小的稳态误差/更小的抖动
Step6  加负载后：重测 TFF（负载摩擦可能翻倍）
```
**为什么这个顺序**：TFF 解决"主要矛盾"（摩擦），Ki 只负责"补残差"，Kp 负责"响应速度"。顺序倒了就会互相打架（比如先加 Ki 再补 TFF → 积分被前馈顶成超调）。

### 4.5 ★★★★☆ 反馈滤波（本工程**尚未加**，下一步候选）

速度反馈来自编码器差分，200 Hz 采样下**量化噪声被 Kp 放大** → 抖动。做法：一阶低通 `v_f = v_f + α(v_raw − v_f)`，`α = dt/(τ+dt)`，τ 取 5~20 ms。

- 代价：相位滞后 → 有效带宽下降 → 不能太狠（τ 应 ≪ 1/(2π·目标带宽)）。
- 判据：抖动变小但阶跃响应不过分变慢。

### 4.6 ★★★☆☆ 提高控制频率（200 Hz → 1 kHz）

延时 = 采样 + 计算 + 传输 ≈ 1 个周期。200 Hz → 5 ms 延时；1 kHz → 1 ms。
CAN 带宽允许（8 字节 @1Mbps ≈ 130 µs，1 kHz 下占 13%）。**但**：1 kHz 下按位打包/解包的全部计算都要挤进 1 ms，且外环增益要做相应调整（`dt` 变了，Ki 的等效强度变 5 倍）。

### 4.7 ★★★☆☆ 抗积分饱和（本工程已实现）

只在"未被限幅"时积分；受限时冻结（甚至回退）。没有它，长时受限后积分攒到巨大值 → 一旦解除就猛冲（超调）。

### 4.8 ★★★☆☆ 重力前馈（竖直安装时需要）

若关节竖直，负载重力产生 `τ_g = m·g·L·cos(θ)` 的恒定偏置。做法：`T += τ_g(θ)`。**与摩擦前馈分开**：摩擦与**速度方向**有关，重力与**位置**有关。
**辨识方法**：让轴停在几个不同角度、读维持不动所需的 `T` → 拟合 `τ_g(θ)`。

### 4.9 ★★☆☆☆ S 曲线 / 轨迹整形（位置模式）

目标位置不是阶跃给，而是"加速段-匀速段-减速段"（梯形/S 形），避免冲击。本工程位置模式目前只用 `RATE`（deg/s²）做一阶限速，够用但可升级。

### 4.10 ★★☆☆☆ 扰动观测器 DOB / 力矩估计

用"模型预测力矩 − 实际力矩"估出扰动（摩擦+负载），直接补偿。属于进阶，先把 4.1~4.6 做扎实再上。

## 6. 实验手册：用一晚上把参数标定出来

> 通用前提：`#LOG 1`、`#EN`、`#WD 0`、`#LIM T 2`（安全网）、`#TEL 100`（10 Hz 遥测）。**每次只改一个参数**，跑 30 s，记录数据。

### 实验 1：测静摩擦（起动力矩）
```
#SET KI_V 0 #SET KP_V 0        → 纯前馈模式
#V 10 0 0.00                    → 目标 10°/s，前馈 0
#SETP? 不用。逐步加大：
#V 10 0 0.05 → 0.10 → 0.15 → 0.20 → 0.25   每档 10 s
判据：pos 开始持续变化的那个值 = 静摩擦力矩 τ_s（实测 ≈0.25 N·m）
```

### 实验 2：测动摩擦（维持力矩）
```
#V 10 0 0.30        → 确保能转起来
读 @TEL 的 T：转起来后 T 应在某个值附近波动 → 中位数 ≈ 动摩擦 τ_k（实测 ≈0.10 N·m）
```

### 实验 3：验证内环阻尼（本工程最值得做的一个）
```
A: #V 10 1.0 0.15      （kd=1.0，跟随速度后 T 中位数 = T_A）
B: #V 10 0.3 0.15      （kd=0.3，T 中位数 = T_B）
判据：若 T_B < T_A 明显（预期差 0.1 N·m 量级）→ 内环阻尼确实在吃力矩
```

### 实验 4：增益扫描
```
固定 TFF=0.15, TRATE=20, KD_DAMP=0.3, KI_V=0
KP_V: 0.002 → 0.005 → 0.01 → 0.02   （每档记录 vel 纹波峰峰值）
判据：纹波开始明显变大的前一个值 = 合适上限（典型 0.005~0.008）
再固定 KP_V，Ki: 0.002 → 0.01 → 0.02  （记录稳态误差与低频摆动）
```

### 实验 5：速率/频率极限
```
TRATE: 5 → 20 → 50 → 100   记录"是否出现高频嗡鸣或过冲"
反推：本机 J（惯量）≈ τ/(dω/dt) → 用阶跃响应估惯量，为将来升级 1kHz 做依据
```

## 7. 将来自己写电机固件：路线图

> 目标不是"复刻 8108"，而是**掌握这条链**：CAN ↔ 主控 ↔ 三环 FOC。你已有的资产：Dummy-Robot 蓝本、FOC103 板（F103+DRV8313+INA199+CAN）、`Desktop\foc驱动` 工程、MAXWELL/Motor-CAD 仿真能力。

| 阶段 | 目标 | 关键工作 | 验收 |
|---|---|---|---|
| **P0 通信对齐** | 让自研板子能听懂 MIT 帧 | 复用本工程的 `motor_8108.c` 打包代码；先做"回显应答"（收到 0x201 就回 0x781，数据填假值） | 上位机 `#PING`/`#STAT` 能连通、反馈帧格式对 |
| **P1 电流环** | 三电阻/单电阻采样 + SVPWM + PI | ADC 注入组采样、Clarke/Park、SVPWM 中点平衡、电流零漂校准 | 给定 Id=0/Iq=常数，实际电流跟随误差 <5%，带宽 >2 kHz |
| **P2 编码器与角度** | 电角度与机械角度解算 | MT6816/AS5047 SPI 读取、多圈计数、零位标定、电角度对齐（给 d 轴注入看转差） | 手转一圈角度单调无跳变；电角度对齐后能小电流转动 |
| **P3 速度环 + CAN 控制** | 复刻 MIT 行为 | 速度环 PI + 前馈、MIT 帧解码、反馈帧打包（含 ERR/温度） | 用本工程的串口协议直接驱动它，表现近似 8108（起步/纹波对比） |
| **P4 位置环 + 高级** | PD/阻抗/轨迹 | 位置 PD、S 曲线、摩擦前馈、观测器 | 重复定位精度、带宽、抗扰测试 |

**P0→P1 之间最容易翻车的地方**（提前知道能省一周）：
1. **电流采样时机**：必须在 PWM 中心对齐的"下管全通"窗口采样，否则噪声巨大；
2. **电角度对齐**：编码器零位与电角度机械偏移必须标定，否则一动就抖/原地打转；
3. **死区与开通延时**：不加补偿会导致低速脉动；
4. **实时性**：20 kHz 电流环里禁止浮点除法/`printf`；用查表或定点；
5. **保护**：过流/过温/堵转必须硬件+软件双保险（我们 8108 的 ERR 位就是这一层）。
