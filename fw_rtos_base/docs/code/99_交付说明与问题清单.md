## 4. 问题清单（全部经我复核，附证据行号）

> 说明：以下都是**文档撰写过程中被逐个函数核对"逼出来"的真问题**，不是猜的。P1 建议尽快修，P2 排期修，P3 顺手改。

### P1 · 正确性（5 条）

**P1-1　快照 seqlock 读侧有缺陷（会拿到未填充/旧数据）**
- 证据：`mcu_bsp/Motor/motor_8108.c:150 J8108_CopySnapshot()`
  ```c
  do {
      s1 = s_snap_seq;
      if ((s1 & 1u) != 0u) { continue; }      /* ← 跳到 while 判断，跳过 memcpy */
      memcpy(out, (const void *)&s_snap, sizeof(J8108_Snapshot_t));
      s2 = s_snap_seq;
  } while (s1 != s2);
  ```
- 问题：`continue` 后 `s2` 仍是**上一轮的旧值**（首轮就是**未初始化**，属未定义行为）；恰好 `s1 == s2` 时循环退出但**一次都没拷贝** → 调用方拿到未填充/陈旧快照。
- 影响：屏/日志/遥测可能显示错数据（概率低但存在，且属于 UB）。
- 建议改法（3 行，等价语义、无接口变化）：
  ```c
  for (;;) {
      s1 = s_snap_seq;
      if ((s1 & 1u) != 0u) { continue; }   /* 正在写：重试 */
      memcpy(out, (const void *)&s_snap, sizeof(J8108_Snapshot_t));
      s2 = s_snap_seq;
      if (s1 == s2) { break; }
  }
  ```

**P1-2　`#STAT` 回包会超过 127 字节上限被截断（已经可能发生）**
- 证据：`Task/Src/CmdRx_Task.c:357` 的格式串 + `mcu_bsp/proto/proto_tx.c:16 PROTO_LINE_MAX (127u)`。
- 实算：**常见情形 135 字节、最坏 157 字节 > 127** → `snprintf` 截断，尾部 `hold=`/`set=` 直接消失（`rx/tx` 涨到 6 位数就开始出现）。
- 影响：排查时看到的 `#STAT` 不完整，容易被误判成"命令没生效"。
- 建议改法：拆成两行（`@OK STAT ...` + `@OK STAT2 ...`），或把 `rx/tx/hold` 改紧凑（如 `rx=%lu` 换成 `rx=%u` 并在超 6 位时打印 `rx=1.2M`）。**这会改协议回包格式，需要你拍板。**

**P1-3　堵转保护在速度模式下形同虚设（门限高于限幅上限）**
- 证据：`mcu_bsp/ctrl/ctrl_core.c:72 p->stall_nm = 8.0f;` vs `:65 p->tmax_nm = 7.5f;`，判据在 `:339 if ((f_abs(t_nm) > p->stall_nm) && ...)`。
- 问题：速度模式里力矩被 clamp 到 ±7.5 N·m，**永远够不到 8.0** → 堵转报警不会触发（阻尼/位置模式下电机自己算力矩，才可能触发）。
- 建议改法：`stall_nm` 默认降到 **5.0**（留 2.5 N·m 余量），并给它加 `#SET` 键方便改。

**P1-4　摩擦前馈在"目标为 0"时仍施加常值力矩（停车时顶着不动）**
- 证据：`mcu_bsp/ctrl/ctrl_core.c:448`
  ```c
  t = (p->kp_v * e) + s->integ + s->tff + ((s->set_applied >= 0.0f) ? p->tff_nm : -p->tff_nm);
  ```
- 问题：`set_applied == 0`（例如 `#V 0` 停下后）判据取 `+`，于是 **+TFF 常值偏置**一直存在（例如 TFF=0.15 → 轴被 0.15 N·m 推着，可能缓慢爬行/顶死）。
- 建议改法：加死区 `if (f_abs(s->set_applied) < 0.5f) { tff = 0.0f; }` 或用"最后一次非零方向的符号"。

**P1-5　`CANTransmit()` 无界自旋等邮箱（同类问题的更严重版本）**
- 证据：`mcu_bsp/can/bsp_can.c:99` — `while (HAL_CAN_GetTxMailboxesFreeLevel(...) == 0) {}` **没有任何超时**。
- 影响：无 ACK/总线异常时**永久卡死调用它的任务**。8108 不经过它（已用受控的 `motor_8108` 发送），但 c620/dm_j4310 会。
- 建议改法：与 `motor_8108.c` 同样加 guard（≤500 次≈50µs），超时返回失败码。
