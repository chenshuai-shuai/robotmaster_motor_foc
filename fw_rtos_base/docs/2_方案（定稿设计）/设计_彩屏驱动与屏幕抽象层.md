## 1. 目标 / 非目标

**目标**
1. 一个**统一屏幕插口**（A 板 OLED 口）+ 一套**屏幕驱动契约**，换屏=换宏（用户原话："做成一个模块化的插口"）。
2. 本轮新增：**ST7735S 128×160 彩屏驱动**（含汉字），能跑现有 4 页监护界面。
3. 界面层与驱动层彻底分离：**界面只调 `Disp_*` 契约**，不认识任何具体屏。
4. 保持控制任务（prio5 / 200Hz）时基零劣化；不引入新的长阻塞/长自旋。

**非目标（本轮不做）**
- 触屏、图形库（LVGL 之类）、视频级刷新率
- 改 CubeMX 工程配置（.ioc 不动；驱动**自带 GPIO/AF/SPI 初始化**，沿用 `bsp_key`/`OLED.c`/`Led_Task` 的既有风格）
- 重做 4 页 UI 的信息结构（内容沿用，只换皮）

## 3. 硬件约束（全部取证，不猜）

### 3.1 A 板 OLED 口 = 我们的唯一屏幕插口

官方《开发板用户手册》§1.17（`F:\下载\RoboMaster开发板A型\官方资料\...pdf` 与官网 PDF，本机 temp 已存档）：

```
J17 (11257W90-7P-S, 1.0mm 卧式 7P)：
   pin1 BUTTON_AD (PA6)   ← AD 分压按键（官方 OLED 模块的五向键）
   pin2 OLED_MOSI (PA7)
   pin3 OLED_SCLK (PB3)
   pin4 OLED_DC   (PB9)
   pin5 OLED_RST  (PB10)
   pin6 GND
   pin7 VCC_3V3
```

**引脚复用核对（本次已 grep 全工程 + 对官方手册）**

| 引脚 | 现状 | 彩屏要用它做什么 | 结论 |
|---|---|---|---|
| PB3 | 闲置（**默认 JTDO**） | SPI1_SCK | ⚠️ 必须先 **关闭 JTAG**（只留 SWD）：`__HAL_AFIO_REMAP_SWJ_NOJTAG()`；工程里目前**没有任何 SWJ 配置**，属于新增必需项 |
| PA7 | 闲置 | SPI1_MOSI | ✅ 与 SPI1(AF5) 一致 |
| PB9 | 现软 I2C 的 SDA | 彩屏 DC | ✅ 宏切换后释放（同一时间只有一块屏） |
| PB10 | 现软 I2C 的 SCL | 彩屏 **CS**（必须软件控制：**CS 低=选中 LCD、CS 高=选中算字库芯片**） | ✅ 同上 |
| PA6 | 闲置（OLED 口 BUTTON_AD，线上有 47pF/ESD） | 彩屏 **SDO（读字库的 MISO）** | ⚠️ 当数字输入用**必须实测**（见 §11 风险 R2；硬件 SPI1_MISO 正好也是 PA6） |
| 3V3 | 端口供电 | 彩屏 + 背光 | ⚠️ 官方电源树：3.3V@250mA（对外供电档），**需实测背光电流**（见 R3） |
| GND | — | — | ✅ |

**已被占用、绝对不要碰**：IMU=SPI5(PF6/7/8/9)+PB8(INT)+PB5(加热)+PE2/PE3(磁力计)；KEY=PB2；8×LED=PG1..PG8；红/绿 LED=PE11/PF14；电源控制=PH2..PH5；SD=PC8..PC12/PD2/PE15；CAN1=PD0/1；CAN2=PB12/13；USART6=PG9/PG14。

### 3.2 引脚预算：8P 怎么装进 5 根线（方案核心算术 · 已按原理图定案）

**模块规格（商家接口原理图 + 引脚表，2026-09-19）**

| 项 | 规格 |
|---|---|
| 分辨率 | **160×128**（1.8" 面板横屏口径；竖屏即 128×160，以自检画面实测为准） |
| 驱动 IC | **ST7735**（S 系列，序列通用） |
| 供电 | 3.3~5V 宽压 → 我们取 **3V3**，与 A 板逻辑电平一致 |
| 接口 | **8P / 2.54mm 排针**；商家标注"排针最少只需 4 个 IO 即可驱动" |
| 板载字库 | GB2312 点阵（12/16/24/32 号），**数据经 SDO 读出** → 必须给它一根 MISO |

**原理图（J1）逐脚 → A 板 OLED 口**

| # | 模块脚 | 原理图网络 | 落到 A 板 OLED 口 | 说明 |
|---|---|---|---|---|
| 1 | VDD | VDD | 端口 **3V3** | |
| 2 | GND | GND | 端口 **GND** | |
| 3 | SDI | MOSI | **PA7**（SPI1_MOSI） | |
| 4 | SCL | SCK | **PB3**（SPI1_SCK，10.5MHz） | PB3 默认是 JTDO → **必须先关 JTAG** |
| 5 | CS | CS/片选 | **PB10** | ⚠️ **一根 CS 管两个从机且反相**：`CS 低=选中 LCD`、`CS 高=选中字库芯片`（例程 `ZK_CS_*` 同此逻辑）→ **必须 MCU 控制，不能接地** |
| 6 | SDO | MISO | **PA6**（正好是 SPI1_MISO） | 读字库用；PA6 线上有 OLED 口按键分压/47pF → **必须实测**（风险 R2） |
| 7 | RS | D/C | **PB9** | = DC，仅对 LCD 有效 |
| 8 | BLK | 背光控制（**高=亮**） | **3V3（固定点亮）** | 5 根线已全用满 → 无调光 |

→ **结论：这块屏正好把 OLED 口的 5 根可编程线全部吃满**（PB3/PA7/PB9/PB10/PA6），换来 **LCD + 板载字库都能用**；代价是**背光不能调光**。

**备选（只在"不要字库/要调光"时才用）**

| 变体 | 差异 | 得到 | 失去 |
|---|---|---|---|
| **A（推荐）** | 如上表：CS=PB10、SDO=PA6、BLK=3V3 | LCD + 板载字库（四种字号汉字） | 无调光 |
| B | SDO 不接、CS→GND、**BLK=PB10** | 背光调光 | 字库**彻底不可用**（CS 常低 → 字库永不被选中）→ 汉字只能内置点阵 |
| C | SDO 不接、CS=PB10、**BLK=PA6** | CS 可控 + 调光 | 无字库（SDO 没落点）；同样要实测 PA6 |
| D（排障回退） | 放弃硬件 SPI，PB3/PA7 位翻 | 接线不变，仅降速 | 速度约 1/4 |

> **⚠️ 与上一版方案的两处修正**（以接口原理图为准，商家"引脚定义表"有误）：
> 1. **第 6 脚是 SDO（MISO），不是 RST** —— 例程 `zk.c` 正是用这根线读字库 → **字库可读，汉字不用退到内置点阵**；
> 2. **整块模块没有 RST 脚** —— 靠板上 RC 上电复位；万一屏状态卡死，用 ST7735S 软复位命令 `0x01(SWRESET)` 兜底（所以不需要为复位留线）。

> **💡 BLK（背光）实测结论（2026-09-19，用户实测）**：**BLK 悬空 = 背光默认点亮**（模块内部上拉到 VDD，与原理图"高有效"一致）。
> 所以 **BLK 可以不接**（转接线省一个分叉）；但推荐仍把它搭到端口 **3V3**（同一个电源网络，白送、不占信号线）：**确定性强**，不依赖内部上拉强度/批次差异，也免去悬空脚受噪声偶发闪烁。
> 无论接不接，**都不影响 5 根信号线的预算**（BLK 从来不是信号线）；**调光**只能牺牲字库（变体 B/C）或在转接线上加手动小开关。

### 3.3 时间预算（先把账算清楚，再定刷新策略）

| 场景 | 数据量 | @10.5MHz | @21MHz(超频) |
|---|---|---|---|
| 全屏 128×160×2B | 40,960 B | **31.2 ms** | 15.6 ms |
| 一页整行带 160×16×2B | 5,120 B | 3.9 ms | 2.0 ms |
| 单行 160×2B | 320 B | 0.24 ms | 0.12 ms |
| （对照）现 OLED 软 I2C 全帧 | 1,024 B | ≈40 ms/帧（10Hz 占该任务 ~40%） | — |

- ST7735S 写入时序上限约 **15MHz**（tSCYCW≈66ns，器件手册口径；**实现前用模块手册复核一次**）→ **10.5MHz（APB2 84MHz ÷8）是保守且合规的选择**，21MHz 属于超频不作默认。
- 结论：**必须有局部刷新**（脏矩形）。10Hz 屏刷、只有 1~2 个区域变化时，每帧 4~8ms，占 prio3 任务 <8%，与现在相当但画面从 1KB 单色变 40KB 彩色。

## 4. 方案总览（分层 + 方块图）

```
┌──────────────────────────── 数据层（不动） ────────────────────────────┐
│ J8108 任务 prio5 (200Hz) → seqlock 快照 + Ctrl_State                   │
└───────────────────────────────┬────────────────────────────────────────┘
                                │ 只读
┌───────────────────────────────▼────────────────────────────────────────┐

└───────────────────────────────┬────────────────────────────────────────┘
                                │ 统一显示契约
┌───────────────────────────────▼────────────────────────────────────────┐
│ 屏幕抽象层  mcu_bsp/disp/disp_port.h   （唯一的"接口契约"）             │
│   Disp_Init / Disp_Info / Disp_Clear / Disp_FillRect / Disp_Text        │
│   Disp_Line / Disp_Rect / Disp_Flush / Disp_Brightness / Disp_SelfTest  │
│   规格：逻辑分辨率、颜色位深(1=单色 / 16=RGB565)、字号档位              │
└───────────────┬────────────────────────────────┬───────────────────────┘
                │ 由功能宏二选一（编译期互斥）    │
┌───────────────▼─────────────────┐  ┌───────────▼─────────────────────────┐
│ 驱动A: disp_sh1106_i2c.c        │  │ 驱动B: disp_st7735s_spi.c           │
│  （现 OLED.c 的能力，收口到契约）│  │  硬件 SPI1 + CS/DC GPIO             │
│  PB10=SCL / PB9=SDA 软 I2C      │  │  PB3=SCK PA7=MOSI PA6=MISO(SDO)     │
│                                 │  │  PB9=RS  PB10=CS(低=LCD 高=字库)    │
└───────────────┬─────────────────┘  └───────────┬─────────────────────────┘
                │                                │
┌───────────────▼────────────────────────────────▼───────────────────────┐
│ 物理层：GPIO / AF5 / SPI1 / （可选）DMA2_Stream5_Ch3                   │
│ 转接线上固定：BLK→3V3、VDD→3V3、GND→GND（CS 必须接到 PB10，不可接地）  │
└────────────────────────────────────────────────────────────────────────┘
```

**为什么这么切**
1. **用户诉求直达**：换屏 = 换宏；页面代码、数据层、按键逻辑全不动。
2. **单色/彩色统一**：单色屏把 `color` 当 0/1（非 0 即点亮），字号档位由 `Disp_Info` 报告，页面层按"字符格"排版而不是按像素。
3. **可静态验证**：`verify_dev.py` 能断言"UI 层只出现 `Disp_*` 调用、不出现任何驱动私有符号"，从机制上保证"换屏不改页面"。

## 6. 统一显示契约（`mcu_bsp/disp/disp_port.h` 草案）

```c
typedef enum { DISP_FONT_SMALL = 0, DISP_FONT_MED, DISP_FONT_BIG } Disp_Font_e;

typedef struct {
    const char *name;        /* "SH1106-I2C" / "ST7735S-SPI" —— 开机日志&自检打印 */
    uint16_t w, h;           /* 逻辑分辨率（按当前旋转方向） */
    uint8_t  color_bits;     /* 1 = 单色, 16 = RGB565 */
    uint8_t  font_w[3], font_h[3]; /* 三档字号的字符点阵尺寸（页面层排版用） */
    uint8_t  has_brightness; /* 是否支持调光 */
} Disp_Info_t;

void               Disp_Init(void);            /* 自带 GPIO/AF/SPI 初始化，幂等 */
const Disp_Info_t *Disp_Info(void);

void Disp_Clear(uint16_t color);                        /* 全屏填充 */
void Disp_FillRect(int16_t x,int16_t y,int16_t w,int16_t h,uint16_t color);
void Disp_Text(int16_t x,int16_t y,const char *s,uint16_t fg,uint16_t bg,Disp_Font_e sz);
void Disp_TextCn(int16_t x,int16_t y,const char *gbk,uint16_t fg,uint16_t bg); /* 汉字（实现可选） */
void Disp_Line(int16_t x0,int16_t y0,int16_t x1,int16_t y1,uint16_t color);    /* 曲线/边框用 */
void Disp_Rect(int16_t x,int16_t y,int16_t w,int16_t h,uint16_t color,uint8_t filled);
void Disp_Flush(void);                     /* 提交"脏区"（单色屏=页推送；彩屏=脏矩形） */
void Disp_Brightness(uint8_t pct);         /* 不支持者空实现 */
uint8_t Disp_SelfTest(void);               /* 0=OK，非0=失败码（开机画测试图并自检） */
```

**语义约定（写进头文件注释，避免以后扯皮）**
1. **坐标原点左上**，`x∈[0,w)`、`y∈[0,h)`，越界裁剪不崩（驱动内部钳位）。
2. **颜色**：彩色屏直接用 RGB565；单色屏 `color != 0` 即点亮。页面层统一用**主题色宏**（`UI_C_OK/UI_C_WARN/UI_C_ERR/UI_C_DIM/UI_C_BG/UI_C_FG`），由驱动按 `color_bits` 降级。
3. **`Disp_Flush()` 是唯一"上屏"动作**：页面层画完调一次；驱动自己决定推多少（脏矩形/整页）——**刷新策略归驱动，页面层不知道也不关心**。
4. **不许在契约函数里 `vTaskDelay` 长阻塞**：单次调用预算 <5ms（prio3），DMA 版本要求 <1ms。
5. **数据门控不变**：不新鲜时页面层照旧只显示 `AGE never / LINK DOWN`，绝不打旧数值。

## 7. ST7735S 驱动设计（本轮新增）

### 7.1 物理层
- **硬件 SPI1**：PB3=SCK、PA7=MOSI、**PA6=MISO**（AF5），主机模式，8bit，MSB first，CPOL=0/CPHA=0（SPI 模式 0）；`NSS` 由软件管（**CS=PB10**）。
- **⚠️ CS 是"双从机反相开关"（本方案最容易踩的坑）**：`CS 低 = 选中 LCD`、`CS 高 = 选中字库芯片`。画屏期间必须保持 CS 低；读字库要拉高，**读完必须拉回低**，否则后续 LCD 数据全被写进字库芯片（现象：花屏/不显示）。
- 速率：**84MHz ÷8 = 10.5MHz**（默认，LCD 用）；**读字库先用 ÷16 = 5.25MHz**（稳）。实测稳定后可评估 ÷4（超器件手册，不默认开）。
- 初始化顺序（**坑**）：① 开 GPIOA/GPIOB 时钟 → ② `__HAL_AFIO_REMAP_SWJ_NOJTAG()`（**必须在配 PB3 之前**，否则 PB3 归属 JTDO，屏必黑）→ ③ 配置 PB3/PA7/PA6 为 AF5，PB9(RS)/PB10(CS) 为推挽输出 → ④ 开 SPI1 时钟 + 配置 → ⑤ CS 拉低 + ST7735S 初始化序列 → ⑥ 清屏。
- **没有 RST 脚**：模块靠板上 RC 上电复位；软件兜底用 ST7735S 的 `0x01 SWRESET`（异常时可软复位，比"拔电重插"体面）。
- **不用 CubeMX**：全部在本驱动内部完成（与 `bsp_key`/`OLED.c`/`Led_Task` 同风格），`F427IIH6_CAN.ioc` 与生成区一行不动。

### 7.2 ST7735S 初始化序列
直接采用**你给的模块官方例程**（绿深 1.8" 带字库，`HARDWARE/LCD/lcd_init.c`）里的序列：`0x11` 睡眠退出 → `0xB1/B2/B3` 帧率 → `0xB4` → `0xC0..C5` 电源 → `0x36` 方向 → `0xE0/E1` gamma → `0x3A=0x05`(65k) → `0x29` 开显示。
**注意**：该例程 `0x36` 与 `LCD_Address_Set` 的坐标偏移是按它自己的板子写的（`USE_HORIZONTAL` 0/1/2/3），移植时要按我们的屏朝向**重新标定偏移**（ST7735S 128×160 常见 0/0 或 0/24 列偏移），用"画 1 像素边框 + 四角打点"自检画面定标——这也是 `Disp_SelfTest()` 的第一个用途。

### 7.3 显存与刷新策略（三选一，推荐 A）

| 方案 | RAM | 每帧推送量 | 评价 |
|---|---|---|---|
| **A. 全帧 40KB + 脏矩形**（推荐） | 40,960 B 静态数组 | 只推变化矩形 | RAM 够（58.7→~100KB/192KB）；局部刷新最省时间；画线/曲线可以随便算 |
| B. 行带 4KB（16 行） | 4,096 B | 每帧按带重画+推送 | 省 RAM，但每帧都要重算整带内容，代码更绕 |
| C. 无显存直写 | 0 | 立即写屏 | 最省 RAM，但会闪、局部刷新做不了、曲线画不了 |

- **A 的脏区记账**：`Disp_FillRect/Text/Line` 更新一个 `dirty{x0,y0,x1,y1}` 包围盒；`Disp_Flush()` 把该矩形按"行带"切块推送（ST7735S 只需设一次窗口 `0x2A/0x2B/0x2C` 后连续写像素）。
- **局部刷新的粒度**是**行带**（例如 16 行）：一次设定窗口后推 160×16×2=5,120B ≈3.9ms@10.5MHz。4 页界面正常刷新只涉及 1~2 条带 → **每帧 4~8ms**。
- **`Disp_Flush()` 之后清脏区**；整屏清屏走"全屏一条矩形"的路径。

### 7.4 DMA（S2 之后再加，非首版必须）
- SPI1_TX → **DMA2_Stream5 / Channel3**（已核对 CubeMX 器件库映射表；本工程已用：S1=USART6_RX(Ch5)、S3/S6=SDIO(Ch4) → **不冲突**）。
- 收益：一次行带推送 CPU 占用从 ~4ms 降到 ~0（只等 DMA 完成信号量），刷屏对 prio3/prio4 任务的影响进一步降低。
- 风险：DMA 配置写错会静默不出图 → 首版先**轮询（HAL_SPI_Transmit）**跑通，再加 DMA 做 A/B 对比（日志打 `flush_ms`）。

### 7.5 与任务/优先级的关系
- 屏刷仍在 **Monitor 任务 prio3**（10Hz）里；控制任务 prio5 完全不受影响。
- 开机自检结果与屏型号进日志（英文）：`disp: ST7735S 128x160 (SPI1 10.5MHz) selftest=OK`。
- 自检失败**不阻塞启动**：只打 E 级日志并把 `Disp_Info()` 标为不可用，界面层降级为空操作。

## 8. 汉字方案（原理图确认 SDO 可读 → **首版走板载字库**，内置点阵做备份）

**字库怎么读（例程 `zk.c` 已给出完整协议，可直接移植）**

```
① CS = 高            （选中字库芯片；此时 LCD 被取消选中）
② 发 0x03 + 3 字节地址（24 位，高→低）
③ 连续读 n 个字节     （n = 24 / 32 / 72 / 128 对应 12×12 / 16×16 / 24×24 / 32×32）
④ CS = 低            （切回 LCD —— 忘了这步屏就花）
```

- **地址公式（GB2312）**：`Addr = ((MSB-0xA1)*94 + (LSB-0xA1)) * n + BaseAdd`
  汉字区（0xB0~0xF7）用：`((MSB-0xB0)*94 + (LSB-0xA1) + 846) * n + BaseAdd`
- **BaseAdd**：12×12 → `0x000000`，16×16 → `0x02C9D0`，24×24 → `0x068190`，32×32 → `0x0EDF00`
- **点阵格式**：纵向 8 点/字节、**高位在上**（与彩屏"每像素 16bit"不同 → 转换函数 + 字符缓存）

**驱动内部设计**
- `Disp_TextCn()` = **字符缓存 + 按需读字库**：常用字（界面固定文案）首次读出后缓存，之后直接命中缓存（例如 32 字 × 32×32 ≈ 4KB 缓存）；数字/单位这类每帧变化的用 ASCII 字体（走 SPI 直写）。
- 读字库时钟：**先用 5.25MHz（SPI1 ÷16）**；若 PA6 作 MISO 实测不过关 → 切"软件位翻读"（PB3/PA7 临时切 GPIO，读完切回 AF5），封装在同一函数里，上层无感。
- 编码口径：字库只有 **GB2312 简体**（界面文案避开 GBK 扩展/生僻字）；页面层用 GB2312 编码字符串传入。

**备份路线（同一 `Disp_TextCn()` 的第二实现）**：若 PA6 实测失败、或以后换用不带字库的模块 → 改用**固件内置点阵**（PC 端脚本从字库/字体抽 60~100 个界面用字，16×16 约 3.2KB）。两条路线**页面层零改动**，只在驱动内部换实现 + 一个宏。

| 方案 | 需要引脚 | 得到 | 代价 |
|---|---|---|---|
| **A. 板载字库（首版）** | **SDO=PA6** | 12/16/24/32 四种字号汉字，随取随用，不占 Flash | 一根线 + CS 反相时序要小心；依赖模块字库芯片 |
| B. 固件内置点阵（备份） | 无 | 不依赖模块，最稳 | 只能显示编进去的字；16×16 三四十个字的量级 |

## 9. 4 页界面迁移（内容不变，换皮）

- **朝向**：竖屏 128×160 起步（与现在"8 行文本"的心智最接近）；横屏 160×128 作为宏可选项，本轮不做。
- **排版**：8 行 × 16 列（字号 BIG 16px）或 10 行 × 20 列（字号 SMALL）——由 `Disp_Info_t.font_*` 决定，页面层按"字符格"排版，**同一份代码在 OLED(6×8) 和彩屏(8×16/12×24) 上都能排**。
- **配色**（RGB565 主题宏）：
  | 语义 | 彩色 | 单色降级 |
  |---|---|---|
  | 正常 value | 白 | 亮 |
  | OK / LINK UP | 绿 `0x07E0` | 亮 |
  | WARN（温度预警、限幅） | 黄 `0xFFE0` | 亮 |
  | ERR（电机报错、链路断、ESTOP） | 红 `0xF800` | 亮（可加闪烁，由页面层做） |
  | DIM（单位、提示行） | 灰 `0x8410` | 暗/不画 |
- **门控语义不变**：`rx_count==0` → `AGE never  LINK DOWN`；`age≥200ms` → `LINK DOWN`（英文、逐字保留，既有静态断言会检查这些字符串）。
- 页面层文件名策略：**S1 阶段保持 `Task/Src/Oled_Task.c` 文件名不变**（内容改为只调 `Disp_*`）→ 现有 `verify_dev.py` 里针对该文件的多条断言（`AGE never  LINK DOWN`、`s_last[row]` 局部刷新、`%luL %luB`）继续有效，改动面最小；S3 阶段若改名（`Ui_Pages.c`）则**同一提交里同步改断言**。
