# 规范 · 功能宏与模块化（工程化收口）

> **用户诉求（2026-09-19）**：把工程里现有功能都做成"宏接口"，好处是①分块调不同模块 ②最后组合起来整体测 ③以后加传感器/模组有章法、更工程化。
>
> **本文回答两件事**：① 现在这套宏**为什么做不到**这些（带证据）② 要做到得立哪些规矩、怎么落地、代价多大。
> 与显示子系统方案的关系：`docs/2_方案（定稿设计）/设计_彩屏驱动与屏幕抽象层.md` + `docs/2_方案（定稿设计）/编码方案_彩屏驱动与屏幕抽象层.md` 里为显示层写的机制（契约头 + 文件级 `#if` + 依赖 `#error` + 门禁断言），就是本规范的一个**样板实例**。

## 1. 现状盘点（证据）

### 1.1 现有 10 个宏，实际只在 2 个文件里"生效"

```
$ grep -rn "#if.*FEATURE_" Core Task mcu_bsp Device
Core/Src/main.c            : 10 处（全部是"要不要调用 Xxx_Init()"）
mcu_bsp/uart/uart10_def.c  :  2 处（日志口回调注册）
Task/Src/J8108_Task.c      :  1 处（FEATURE_VERBOSE_LOG 日志详略）
总计 13 处
```

**结论**：宏的语义目前只有一个 —— **"开机要不要初始化它"**。它**不裁剪编译**（所有 `.c` 都在 `uvprojx` 里、永远参与编译与链接），也**不切断依赖**。

### 1.2 跨模块调用全是无条件（宏关掉照样链接）

| 调用方 | 被调方 | 位置 | 关掉被调方宏会发生什么 |
|---|---|---|---|
| `Monitor_Task.c` | `Oled_UiDraw()` | `Monitor_Task.c:250` | 屏没初始化，渲染器照样跑 → 往"未初始化的软 I2C 屏"写数据（不崩，但语义是错的） |
| `CmdRx_Task.c` | `Monitor_SetTelPeriod()` | `CmdRx_Task.c:743/759` | `MONITOR_TASK=0` 时 `#TEL` 仍回 `@OK`，但没有任务去发遥测 → **命令回包与行为不一致** |
| `CmdRx_Task.c` | `J8108_ReqStart/ReqResult/ReqClear` | `CmdRx_Task.c:147/152/158` | `FEATURE_J8108=0` 时 `#EN` 走 120ms 握手，永远等不到结果 → 回 `@ERR`（歪打正着，但不是设计出来的） |
| `J8108_Task.c` | `ui_action.h`（仅取 `UI_HOME_HOLD_MS`） | `J8108_Task.c:23` | 控制任务依赖 UI 策略头，方向反了（UI 层依赖控制层才对） |

### 1.3 "关掉的功能仍占工程"

`MDK-ARM/F427IIH6_CAN.uvprojx` 的 `BSP` 组里，即使 `FEATURE_SD_CARD=0 / FEATURE_SD_CLI=0`，这些文件仍然每次全量编译：
`sd_cli.c`、`sd_fs.c`、`sd_diskio.c`、`sd_sdio.c`、`dm_j4310.c`、`c620.c`、`CRSF.c`、`crc8.c` …
（注：Keil 链接器会 GC 掉未被引用的函数，所以 **Flash 不一定变大**；真正的代价是**编译时间、阅读噪音、以及"看起来这个模块还在"的误导**。）

### 1.4 现状评级

| 评级 | 含义 | 模块 |
|---|---|---|
| **B（半合规）** | 有宏、有 Init 门控，但跨模块调用无保护 | `J8108`、`KEY`、`OLED_UI`、`MONITOR_TASK`、`SERIAL_CTRL`、`LED_TASK`、`SD_CARD`、`SD_CLI` |

## 2. 规范：7 条铁律

| # | 铁律 | 为什么 |
|---|---|---|
| **R1** | **宏只做"裁剪"，不做"改行为"**。一个 `FEATURE_X` 只回答"这个模块参不参与"；任何"开/关后逻辑不一样"必须由**参数**（结构体/命令）承担 | 否则宏组合 = 2^n 种行为，没人测得完 |
| **R2** | **依赖必须显式 + 编译期可查**：`feature_config.h` 里写死依赖 `#error`；**禁止靠"反正能链接"** | 现在的洞（§1.2）就是这么来的 |
| **R3** | **文件级隔离**：模块实现 `.c` **全文**被 `#if FEATURE_X ... #endif` 包住 → 未启用时编译成**空对象**（Keil 允许，链接无重复符号） | 这是"关掉就是真的不参与"的唯一干净做法（两个驱动都实现同名函数时尤其关键） |
| **R4** | **一个模块 = 一对文件**：`Xxx.h`（契约头：Init / Status / SelfTest，**任何组合下都能 include**）+ `Xxx.c`（实现，被宏包住）。**跨模块只走契约头** | 头文件不该因为宏而"消失"，否则 include 就编不过 |
| **R5**（2026-09-19 修订） | **两类宏分家**：`CFG_*` = 工程级选择（当前只有 `CFG_PROFILE`）；**板级/硬件常量（引脚、外设实例、屏幕型号）集中到 `board_config.h` 的 `BRD_*`**（K5 决策，与宏分家等价：换板/换屏只改一处，模块代码零改动）；`FEATURE_*` = 功能/任务（跑不跑）。 |
| **R6** | **组合用"预设 profile"，不做 2^n 手工组合**：`CFG_PROFILE` 一个宏选定一组功能宏；`make verify` 只跑这几个 profile | 能把"组合测试"变成可执行的事 |
| **R7** | **安全模块不许被静默裁掉**：控制/保护类（`J8108`/`ctrl_core`）若被关闭，开机横幅 + 日志必须有显式告警（`W` 级），且不得留下"半死"的总线状态 | 关掉电机控制却以为它在管安全 = 事故 |

## 3. 目录与命名规矩

```
Task/Inc/xxx_task.h      ← 契约头（无宏依赖，永远可 include）
Task/Src/xxx_task.c      ← 实现（首行 #include "feature_config.h"，随后 #if FEATURE_XXX 全文包住）
mcu_bsp/<group>/xxx.{c,h} ← 驱动/算法层：同样一对文件；纯逻辑放 _core.c 便于宿主机测试
```

- 命名：`Xxx_Init()` / `Xxx_Status()` / `Xxx_SelfTest()` / `Xxx_*_Api()`
- 契约头**不 include** 任何实现细节头（只 include `<stdint.h>` + 必要的数据结构头）
- 每个模块的 `.c` 顶部注释块必须写：**职责 / 依赖 / 被谁调用 / 时间预算 / 坑**

## 5. 依赖矩阵与非法组合（示例，落进 `feature_config.h` 的 `#error`）

```c
/* ---- 依赖自检（编译期，不做"静默降级"） ---- */
#if FEATURE_MONITOR_TASK && !FEATURE_DISP_UI
#error "FEATURE_MONITOR_TASK requires FEATURE_DISP_UI (renders to the screen)"
#endif
#if FEATURE_SERIAL_CTRL && !FEATURE_J8108
#warning "SERIAL_CTRL without J8108: only #PING/#VER/#STAT/#LOG are meaningful"
#endif
#if FEATURE_SD_CLI && !FEATURE_SD_CARD
#error "FEATURE_SD_CLI requires FEATURE_SD_CARD"
#endif
#if FEATURE_DISP_UI && !(FEATURE_DISP_SH1106_I2C || FEATURE_DISP_ST7735S_SPI)
#error "FEATURE_DISP_UI requires exactly one display driver"
#endif
#if (FEATURE_DISP_SH1106_I2C + FEATURE_DISP_ST7735S_SPI) != 1
#error "exactly ONE display driver must be enabled (same pins)"
#endif
#if !FEATURE_J8108 && FEATURE_CAR_TASKS
#error "..."
#endif
```

**profile 预设**（`CFG_PROFILE` 一个宏搞定，避免手工组合）：

| profile | 内容 | 用途 |
|---|---|---|
| `PROFILE_FULL` | 全部开（当前默认） | 整机组合测试 |
| `PROFILE_DISP_DEV` | 显示 + 串口 + 按键 + LED（**无电机**） | 屏/UI 分块调试（本轮彩屏开发就用它） |
| `PROFILE_MOTOR_DEV` | J8108 + 串口 + LED（**无显示**） | 电机/控制分块调试（保时优先，排干扰） |
| `PROFILE_MINIMAL` | 串口 + 日志 + LED | 板级 bring-up / 串口链路排查 |

## 6. 服务"分块调试"的追加机制：模块自检 + 串口命令

只把宏打通还不够——**调试时最需要的是"我能不能用一条命令问某个模块它还活着吗"**。

- 每个模块提供 `uint8_t Xxx_SelfTest(void)`：返回 0=OK，非 0=失败码（自己做最便宜的自检：读寄存器/回环/CRC 等，**不做破坏性动作**）。
- 串口加一条命令：`#ST <模块>` → 回 `@OK ST disp=0 can=0 key=1` 或 `@ERR 9 module=can code=3`。
- 开机横幅规范化（现在是自由文本 `main.c:150`），改成**机器可读**一行：
  `@BOOT profile=FULL fw=v0.1.61-dev modules=disp:ST7735S,can,j8108,key,led,monitor,sd:0`
  → `verify_dev.py` 与台架脚本可以断言"烧进去的组合 = 我想要的组合"（**防呆：以为开了其实没开**）。

## 7. 门禁（`tools/verify_dev.py` 新增断言）

| # | 断言 | 查法 |
|---|---|---|
| **V9** | 每个 `FEATURE_*` 至少在 2 个文件里被使用（防"声明了没人用"的僵尸宏） | 正则统计 |
| **V10** | 每个模块实现 `.c` 都被自己的宏包住（R3） | 前 5 行内有 `#if FEATURE_`，且 `#endif` 在末行 |
| **V11** | 契约头可在任意组合下 include（R4） | 用 gcc `-fsyntax-only` 单独 include 每个契约头（不定义任何 FEATURE） |
| **V12** | 依赖矩阵与 `#error` 存在且与登记表一致 | 解析 `feature_config.h` 的 `#error` 行，与 §5 表比对 |
| **V13** | **profile 组合编译**：对 4 个 profile 各跑一遍编译检查 | 首版用 gcc `-fsyntax-only` 全文件扫描（不需要 Keil、秒级）；关键 profile 再用 UV4 真编一遍 |

> V13 是这套规范的价值所在：**没有组合编译，"宏接口"就只是文档**。

## 8. 落地顺序（不搞大爆炸式重构）

| 步 | 做什么 | 改动面 | 收益 |
|---|---|---|---|
| **0** | 本文定稿 + 登记表/依赖矩阵确认 | 0（纯文档） | 有据可依 |
| **1** | **显示子系统按规范落地**（S1 的一部分）：契约头 + 文件级 `#if` + `#error` + V9–V13 断言 | 新增 7 文件 + 改 6 文件 | **样板**：以后照抄 |
| **2** | 纯静态收口：补 `Monitor→Disp` 的 `#if` 保护、把 `J8108_Task.c` 里对 `ui_action.h` 的依赖去掉（`UI_HOME_HOLD_MS` 挪到配置）、`feature_config.h` 加依赖矩阵 | 3 个文件，**不改行为** | 消掉 §1.2 的洞 |
| **3** | 模块自检 + `#ST` 命令 + `@BOOT` 规范横幅 | 协议层 + 各模块加一个函数 | 分块调试真正可用 |
| **4** | 逐个把 B 类模块收口（KEY → LED → MONITOR → SERIAL → SD） | 每个模块 3~5 文件 | 组合自由度 |
| **5** | C 类清理：未用库（c620/dm_j4310/CRSF/Device/* 等）**要么收口要么从工程移除（删前备份）** | 视取舍 | 编译更快、阅读更干净 |

> 与"老规矩"的配合：**每步独立提交、独立验收**；步 2/4 属"不改行为"的重构，可以在没有硬件台架的情况下靠 `make verify` 全绿 + 台架回归日志比对放行。

## 9. 代价与预期（先说清楚，免得白做）

| 项 | 说明 |
|---|---|
| **Flash 不一定变小** | Keil 已经 GC 掉未引用函数；这套规范的主要收益是**编译/阅读/调试边界**，不是省 Flash。真正省 Flash 要靠"从未用文件从工程里移除"（步 5） |
| **不动的风险** | 宏组合不测 = 迟早有人烧一个"以为开了其实没开"的固件去台架 → 所以 V13 必须做 |
| **成本** | 步 1（样板）已含在彩屏 S1 里；步 2/3 约半天；步 4 每个模块半小时~1 小时；步 5 视取舍 |
| **禁令** | 不许出现"开了宏 A 就自动改宏 B 的行为"、不许用宏包住**数据结构定义**（结构体定义必须常驻，否则契约头编不过） |
