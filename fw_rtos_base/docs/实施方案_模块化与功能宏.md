# 实施方案 · 模块化与功能宏（工程骨架）

> **用户 2026-09-19 定序**：先把宏体系/接口规范在工程里建立起来（逻辑清晰、便于裁剪与分块测试），**彩屏功能排在其后**。
> 规范条文见 `docs/规范_功能宏与模块化.md`（7 条铁律 R1–R7 + 登记表 + 依赖矩阵 + V9–V13 门禁）。
> 本文 = **怎么一步步落地**：每步改哪些文件、写成什么样、怎么验收、怎么回退。**本轮不含彩屏代码**。

## 0. 目标产物（骨架建成时应该长什么样）

| 产物 | 说明 |
|---|---|
| **配置层** | `Task/Inc/feature_config.h` = 唯一入口：**预设 profile**（FULL / DISP_DEV / MOTOR_DEV / MINIMAL）+ 功能宏展开 + **依赖矩阵 `#error`** + 显示宏互斥 |
| **板级层** | `Task/Inc/board_config.h`（新）：所有**引脚/外设/尺寸**常量集中于此（换板子只改这里），模块里不再散落 `GPIOB/GPIO_PIN_2` 这类裸值 |
| **契约头体系** | 每个模块一对文件：`Xxx.h`（Init/Status/SelfTest，任何组合都能 include）+ `Xxx.c`（全文被 `#if FEATURE_X` 包住 → 未启用=空对象） |
| **分块调试能力** | 每模块 `Xxx_SelfTest()` + 串口 `#ST [模块]` + 机器可读开机横幅 `@BOOT profile=… modules=…` |
| **门禁** | `verify_dev.py` 断言 V9–V13 + `tools/check_profiles.py`（4 个 profile 的编译矩阵）+ `make profiles` |
| **文档** | README/`docs/code` 增补"配置与裁剪"一节；函数地图/流程图重生成 |

**非目标**：本轮不动控制算法、不改协议语义、不做彩屏驱动（彩屏回到 `docs/编码方案_彩屏驱动与屏幕抽象层.md` 的 S0–S5，且从 S1 起天然遵守本规范）。

## 1. 关键设计决策（先定，执行时不犹豫）

| # | 决策 | 取值 | 理由 |
|---|---|---|---|
| K1 | 配置入口 | **不新增顶层入口**，继续用 `Task/Inc/feature_config.h` | 现有 40+ 处 include 不用改，改动面最小 |
| K2 | profile 覆盖方式 | `#ifndef CFG_PROFILE / #define CFG_PROFILE PROFILE_FULL / #endif` | **命令行 `-DCFG_PROFILE=…` 可覆盖** → 编译矩阵不用改文件 |
| K3 | 未启用模块的编译产物 | **严格空对象**（`#else` 分支为空，不提供空桩） | 忘加 `#if` 保护 → **链接失败（fail-fast）**，而不是"静默不做事" |
| K4 | 自检返回值 | `0`=OK；`1..250`=模块自定义失败码（写进契约头注释）；`255`=未启用 | 与 `@ST` 回包一一对应 |
| K5 | 板级常量 | 引脚/外设/尺寸 → `board_config.h`；**任务优先级/周期/栈**留在各模块头 | 硬件与功能解耦，但不动无关的东西 |
| K6 | profile 编译检查 | 快检：`gcc -fsyntax-only -DCFG_PROFILE=…`（秒级，全 profile）；真编：**临时 uvprojx**（XML 里加 `CFG_PROFILE=…`）+ UV4 构建 | Keil CLI 不支持 `-D`，改临时工程文件最干净，且不污染主工程 |
| K7 | 模块登记表唯一数据源 | 放在 `tools/verify_dev.py` 里的 Python 字典 | 门禁能直接读，避免"文档与实现两张皮" |

## 2. 模板（写成什么样）

### 2.1 契约头模板（`Xxx.h`）

```c
/* Xxx.h - 契约头：**任何宏组合下都必须能 include**（只声明/只放结构体定义） */
#ifndef XXX_H
#define XXX_H

#include <stdint.h>

/* 状态/自检码：0=OK，1..250=具体失败，255=模块未启用（合约：不得被宏包住） */
typedef struct { uint8_t ok; uint32_t cnt; } Xxx_Status_t;

void                 Xxx_Init(void);       /* 幂等；调度器启动前调用；未启用时符号不存在（调用点须 #if 保护） */
const Xxx_Status_t  *Xxx_Status(void);     /* 只读；未启用时不存在 */
uint8_t              Xxx_SelfTest(void);   /* 非破坏性自检（读寄存器/回环/CRC）；不做动作 */

#endif /* XXX_H */
```

### 2.2 实现文件模板（`Xxx.c`）

```c
/* Xxx.c - 职责 / 依赖 / 被谁调用 / 时间预算 / 坑（每个模块必写这段） */
#include "feature_config.h"      /* 必须第一个 include */
#include "board_config.h"

#if FEATURE_XXX                  /* ← 全文包住；未启用 → 编译成空对象（K3） */

#include "Xxx.h"
/* ... 实现 ... */

#else
/* 未启用：本文件为空对象。**不要**在这里加空桩——忘加保护的调用点应当链接失败 */
#endif /* FEATURE_XXX */
```

### 2.3 `feature_config.h` 目标形态（要点）

```c
/* ---------------- 1. 预设组合（选一个） ---------------- */
#define PROFILE_FULL      1u   /* 整机：全部功能（默认） */
#define PROFILE_DISP_DEV  2u   /* 屏调试：UI+串口+按键+LED（无电机） */
#define PROFILE_MOTOR_DEV 3u   /* 电机调试：J8108+串口+LED（无显示） */
#define PROFILE_MINIMAL   4u   /* 最小：串口+日志+LED */

#ifndef CFG_PROFILE                 /* K2：命令行可覆盖 */
#define CFG_PROFILE PROFILE_FULL
#endif

/* ---------------- 2. 由 profile 展开功能宏（勿手工改） ---------------- */
#if   CFG_PROFILE == PROFILE_FULL
#  define FEATURE_J8108         1u
#  define FEATURE_KEY           1u
#  define FEATURE_DISP_UI       1u
#  define FEATURE_MONITOR_TASK  1u
#  define FEATURE_SERIAL_CTRL   1u
#  define FEATURE_LED_TASK      1u
#elif CFG_PROFILE == PROFILE_DISP_DEV
/* ... */
#else
#  error "unknown CFG_PROFILE"
#endif

/* ---------------- 3. 硬件相关选择（不随 profile 变，按插的硬件改） ---------------- */
#define FEATURE_DISP_SH1106_I2C   1u   /* 现役 1.3" SH1106（软 I2C） */
#define FEATURE_DISP_ST7735S_SPI  0u   /* 1.8" 彩屏（SPI1）—— 换屏就改这两行 */
#define FEATURE_VERBOSE_LOG       1u

/* ---------------- 4. 依赖矩阵（编译期自检，语义都在注释里） ---------------- */
#if FEATURE_MONITOR_TASK && !FEATURE_DISP_UI
#  error "MONITOR_TASK requires DISP_UI (它要往屏上画)"
#endif
#if FEATURE_SD_CLI && !FEATURE_SD_CARD
#  error "SD_CLI requires SD_CARD"
#endif
#if (FEATURE_DISP_SH1106_I2C + FEATURE_DISP_ST7735S_SPI) != 1
#  error "exactly ONE display driver (they share the OLED port pins)"
#endif
#if FEATURE_DISP_UI && !(FEATURE_DISP_SH1106_I2C + FEATURE_DISP_ST7735S_SPI)
#  error "DISP_UI 需要一个显示驱动"
#endif
/* 安全模块告警（R7）：不报错但必须开机可见 */
#if !FEATURE_J8108
#  warning "J8108 disabled: motor control & protection are OFF (banner will say so)"
#endif

/* ---------------- 5. 开机横幅（机器可读，台架脚本会断言） ---------------- */
#define BOOT_PROFILE_NAME "FULL"   /* 与 profile 同步 */
```

**`@BOOT` 回包格式（S2 用）**：
```
@BOOT profile=FULL fw=v0.1.61-dev modules=disp:SH1106,serial,j8108,key,led,monitor sd=0 cli=0 car=0
```

#ifndef BOARD_CONFIG_H
#define BOARD_CONFIG_H
#include "main.h"

/* 用户 LED（A 板：红=PE11 绿=PF14 外接 8 灯 PG1..8） */

#define BRD_LED_GRN_PIN     GPIO_PIN_14
#define BRD_LED_EXT_PORT    GPIOG

                             GPIO_PIN_5|GPIO_PIN_6|GPIO_PIN_7|GPIO_PIN_8)
#define BRD_LED_ON_LEVEL    GPIO_PIN_RESET

/* 用户按键：A 板 KEY = PB2，高有效（2026-09-15 实测） */
#define BRD_KEY_PORT        GPIOB
#define BRD_KEY_PIN         GPIO_PIN_2
#define BRD_KEY_ACTIVE_HIGH 1

/* 屏幕口 = A 板 OLED 口（7P，1.0mm）：现役软 I2C 用法 */
#define BRD_SCR_I2C_SCL_PORT GPIOB
#define BRD_SCR_I2C_SCL_PIN  GPIO_PIN_10   /* 口 pin5 */
#define BRD_SCR_I2C_SDA_PORT GPIOB
#define BRD_SCR_I2C_SDA_PIN  GPIO_PIN_9    /* 口 pin4 */
/* 彩屏（ST7735S）用法：SPI1 + CS/RS/MISO */
#define BRD_SCR_SPI_SCK_PORT  GPIOB
#define BRD_SCR_SPI_SCK_PIN   GPIO_PIN_3   /* 口 pin3 */
#define BRD_SCR_SPI_MOSI_PORT GPIOA

#define BRD_SCR_SPI_MISO_PORT GPIOA

#define BRD_SCR_RS_PORT       GPIOB

#define BRD_SCR_CS_PORT       GPIOB
#define BRD_SCR_CS_PIN        GPIO_PIN_10  /* 口 pin5（低=LCD 高=字库） */

## 4. 风险与控制

| 风险 | 控制 |
|---|---|
| **宏组合爆炸** | 只保留 4 个 profile；组合测试交给 `check_profiles.py`，不做人为手工组合 |
| **改崩控制代码** | M1–M3 全是"不改行为"的机械收口，判据是"与 M0 逐字一致"；控制算法零改动 |
| **Keil 工程文件冲突** | 所有 uvprojx 改动集中在 M6（以及彩屏 S1 加文件时），一次做完并立刻 `make build` 验证；Keil GUI 未关闭时不动 uvprojx |
| **"以为开了其实没开"** | `@BOOT` 横幅 + `verify` 的 profile 断言（V13）双保险 |
| **安全模块被静默裁掉** | R7：`#warning` + 横幅显式列出；`MOTOR_DEV` 之外若 `J8108=0`，`#EN` 明确回 `@ERR 4`（不是"没反应"） |
| **一次改太多** | 每步独立提交；每步结束停下给你看结果（老规矩） |
| **OLED.c 引脚宏** | M5 明确"不碰"，留到彩屏 S1 一起收口，避免两头改 |

## 5. 与彩屏方案的关系（顺序与接口都对齐）

- 彩屏不再从"改 `feature_config.h`"开始——**M1 已经把它改好了**；彩屏 S1 只需新增 `FEATURE_DISP_ST7735S_SPI` 的实装与 `disp_port.h`，天然满足 R3/R4/契约头模板。
- 彩屏 S1 的两个驱动文件（`disp_sh1106_i2c.c` / `disp_st7735s_spi.c`）就是**本规范的第一个合规模块**（文件级 `#if` + 契约头 + `Disp_SelfTest()`）。
